# 设计

## 背景

背景见 proposal.md。`SubscriptionPlan` 现有 `UpgradeGroup`、`DowngradeGroup`，但没有计费分组限定。`NewBillingSession` 只检查用户是否持有任意有效订阅，`PreConsumeUserSubscription` 按到期时间选择订阅时也未检查分组。API Key 能否使用分组由认证流程单独判断；自动分组路由在计费前会确定具体的 `UsingGroup`。

## 目标与非目标

**目标：** 将订阅计费资格与 API Key 授权分离；在原子预扣费操作中强制校验实际分组；允许管理员修改套餐配置并立即影响该套餐下的有效订阅。

**非目标：** 不改变用户所属分组、API Key 分组选择、渠道授权，也不将套餐限定复制到已购买的订阅实例。

## 技术决策

1. **在套餐上增加单个可选分组。** 给 `SubscriptionPlan` 新增 `billing_group`，数据库、JSON、Go 和 TypeScript 使用一致名称。空值表示不限制，以兼容旧套餐；非空值必须是已配置的分组。复用管理后台已有分组选项。不复用 `upgrade_group`，因为它负责改变用户所属分组。多分组规则留待独立变更。
2. **在扣费事务内读取套餐当前配置。** 将请求实际路由分组从计费上下文传给 `SubscriptionFunding`，再传入模型层预扣费操作。遍历已有事务和行锁保护下的候选订阅时，读取各套餐当前配置，跳过不匹配的订阅。这是最终校验点；仅做事务外预检查会受到套餐修改或并发变化影响。
3. **预检查也按分组筛选。** 将 `subscription_first` 使用的「有任意订阅」检查改为「有适用于实际分组的订阅」。区分「没有适用订阅」和「有适用订阅但额度用尽」：只有前者触发本次新增的钱包回退；后者继续遵循原有 `allow_wallet_overflow` 规则。按已确认的分组不匹配行为，即使偏好为 `subscription_only`，没有适用订阅时也在钱包额度充足的情况下回退；`wallet_only`、`wallet_first` 的原有优先顺序不变。数据库错误不得被当作分组不匹配而静默回退。
4. **自动分组必须先解析实际分组。** 复用最终选中的具体分组，不使用 API Key 上的 `auto` 值。核对常规中继及适用的任务计费入口；如果无法确定实际分组，不允许受限订阅被扣费。自动分组重试切换分组时，每次尝试都按本次实际分组判断。
5. **前后端展示与校验。** 管理员表单、请求结构、列表列和购买者套餐详情均展示新字段；说明其限制的是订阅扣费而非 API Key 权限。补齐所有受支持语言的翻译。管理接口校验字段；若存在局部更新路径，未提交该字段时保留原配置。

## 风险与权衡

- [旧套餐在管理员配置前仍可跨分组计费] -> 为避免静默改变已售权益，保持兼容，由管理员主动设置限定。
- [修改套餐会影响已售权益] -> 这是明确要求；购买者页面展示当前限定，并沿用管理操作审计。
- [套餐缓存可能延迟生效] -> 更新套餐时失效缓存，原子预扣费读取当前配置，并测试修改后立即生效。
- [自动分组或任务入口可能只有选择器] -> 逐一追踪入口；未确认具体分组时不允许受限订阅扣费。
- [`subscription_only` 回退钱包与名称字面含义不一致] -> 例外仅限「没有适用分组」，不改变订阅额度耗尽后的行为；在界面说明并加入回归测试。

## 迁移方案

通过现有跨数据库迁移路径新增可选套餐字段，默认不限制，兼容 SQLite、MySQL、PostgreSQL。先部署后端再部署前端；旧请求不带新字段时保持原行为。回滚时可以停止使用该字段，不必修改已购买的订阅记录，也无需立即删除数据库列。
