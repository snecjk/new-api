# 提案：限定订阅计费分组

## 背景与原因

当前订阅计费只检查用户是否持有有效订阅，没有核对请求实际使用的分组。用户购买仅打算用于默认组的不限量日卡后，仍可通过 gpt-稳定组 API Key 使用该日卡计费，造成套餐权益跨分组使用。

## 变更内容

- 在订阅套餐管理中新增管理员配置的「计费分组限定」，与现有「升级分组」分别管理。前者决定订阅可以为哪个分组的请求付费，后者决定购买后用户所属分组。
- 服务端按请求实际路由到的分组判断订阅是否可用，并在订阅预扣费时再次校验。API Key 能否使用某分组的现有权限规则不变。
- 如果没有适用于该分组的有效订阅，请求有足够钱包额度时改用钱包计费；钱包额度不足时按现有额度不足规则返回错误，不消耗不匹配的订阅。
- 管理后台和用户购买页面展示套餐的计费分组限定；创建或修改套餐时校验分组是否存在。
- 不把限定复制到已购买的订阅实例。管理员修改套餐后，新配置立即适用于该套餐下已有的有效订阅。
- 旧套餐默认不限制计费分组，直到管理员主动设置，以保持已有套餐行为。

## 能力范围

### 新增能力

- `subscription-group-billing`：按套餐配置的分组限定决定订阅能否为请求计费，以及不匹配时的钱包回退行为。

### 修改现有能力

无。

## 影响范围

涉及订阅套餐数据结构与管理接口、订阅选择和预扣费、计费来源判定、管理后台与购买页面、数据库迁移及回归测试。不改变 API Key 的分组授权规则。
